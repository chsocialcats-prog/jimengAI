# 聊天框回复长度选择设计

## 状态

已获用户确认，待用户审阅规格文档后进入实现计划。

## 目标

在冒险聊天框旁增加“回复长度”选择器，让玩家选择当前会话后续 AI 剧情回复的篇幅。选择只作用于当前会话，不改变全局生成设置，也不影响其他会话。

## 范围与非目标

### 范围

- 在聊天输入框旁显示回复长度下拉框。
- 提供四档：简短、标准、详细、超长。
- 将选择转换为单次 AI 请求的最大输出 token，并附带目标篇幅提示，使模型尽量接近所选长度。
- 选择按会话 ID 保存到浏览器本地存储，重新打开同一会话时恢复。
- 在线、Mock 和离线模式保持现有聊天流程可用；快捷命令不需要剧情长度控制。

### 非目标

- 不新增全局设置项。
- 不修改数据库表结构，也不把长度选择同步到其他设备。
- 不承诺每次回复精确达到某个字数；模型仍可因剧情、结构化标签或服务限制提前结束。
- 不改变上下文压缩预算或摘要长度。

## 用户体验

聊天输入框旁增加一个带标签的下拉框：

| 显示名称 | 请求上限 | 目标篇幅提示 |
| --- | ---: | --- |
| 简短 | 1024 tokens | 约 300–500 字，快速推进 |
| 标准 | 2048 tokens | 约 600–1000 字，默认叙事量 |
| 详细 | 4096 tokens | 约 1000–1800 字，完整描写 |
| 超长 | 8192 tokens | 约 2000–3500 字，展开场景与互动 |

默认选择为“详细”，以解决当前回复偏短的问题。页面加载时优先读取当前会话保存值；没有保存值或值无效时使用默认值。

AI 生成期间禁用选择器，避免一条流式回复中途改变配置；回复结束后重新启用。快捷命令（状态、背包、存档、帮助）继续走原有命令处理，不使用剧情回复长度。

## 技术方案

### 前端

- 在 `renderAdventure()` 的 composer 区域加入 `reply-length-select` 控件。
- 在 `session` 中保存当前会话的 `replyLength` 档位，并通过 `localStorage` 以会话 ID 为键持久化。
- `sendMessage()` 读取当前档位，将档位标识和对应 token 上限放入现有 `metadata` 请求字段。
- `streamChat()` 在线模式发送 `{content, metadata}`；离线 Mock 模式沿用相同参数接口。
- `setStreamingUi()` 同步禁用/启用回复长度选择器。

### 后端

- 复用现有 `ChatRequest.metadata`，不增加新的顶层请求字段。
- 在聊天流入口校验长度档位，只接受四个白名单值；非法或缺失值回退到全局配置的最大回复长度。
- 将解析后的 token 上限传给现有 `DeepSeekClient.stream_chat(messages, max_tokens=...)`。
- 在系统提示中追加当前档位的目标篇幅和写作重点，明确这是本轮回复的长度偏好，不覆盖角色卡、作品规则和结构化输出协议。
- Mock/离线回复接受长度档位参数，保持测试和演示模式接口一致；不为此引入真实模型依赖。

### 数据流

```text
聊天框选择
    ↓
session.replyLength + localStorage(conversation_id)
    ↓
POST /api/conversations/{id}/chat
    { content, metadata: { reply_length } }
    ↓
白名单解析 → max_tokens + 目标篇幅提示
    ↓
DeepSeekClient.stream_chat(..., max_tokens=...)
    ↓
现有 SSE 流式回复
```

## 错误处理与兼容性

- 旧前端不发送 `metadata` 时，后端保持原有全局 `generation.max_tokens` 行为。
- 非法档位不返回 4xx，直接安全回退，避免影响正常聊天。
- API 不支持更高 token 上限时，沿用现有错误处理并显示原有失败提示。
- 当前会话的本地存储损坏或无法解析时忽略并使用默认值。
- 结构化 `<state_delta>`、`<judge>`、`<options>` 块仍由现有过滤器处理，长度提示不得要求模型把这些块展示给玩家。

## 测试策略

### 后端测试

- 四个合法档位分别解析为预期 `max_tokens`。
- 非法档位和缺失档位回退到全局配置。
- 解析后的上限传入 AI 客户端，且不影响现有流式重试行为。
- 目标篇幅提示只在显式选择档位时加入，旧请求的系统提示保持兼容。

### 前端测试

- 聊天框渲染回复长度选择器及四个选项。
- 选择值按会话 ID 保存并在重新渲染时恢复；无效值回退到默认档位。
- 发送请求包含当前档位 metadata，切换会话后不串用另一个会话的选择。
- 流式生成期间选择器被禁用，结束后恢复。
- 离线 Mock 流程继续可以发送并完成回复。

## 验收标准

- 玩家能在聊天框直接选择回复长度，不需要进入全局设置页。
- 选择“超长”后，后续 AI 请求使用 8192 token 上限并收到对应篇幅提示。
- 刷新或重新打开同一冒险会话后，选择保持；切换到另一会话时使用另一会话的设置或默认值。
- 不选择或发送旧格式请求时，现有聊天行为和测试不回归。
