# AGENTS.md 交接说明设计

## 目标

在项目根目录创建一份简洁、可维护的 `AGENTS.md`，让首次进入仓库的 AI Agent 能快速理解项目、运行验证，并在不破坏用户现有工作的前提下继续开发。

## 采用方案

使用单个根目录 `AGENTS.md`，控制在约 80–120 行。当前项目规模不需要为 `backend/` 和 `frontend/` 分别维护嵌套说明。

## 文档结构

1. 项目定位：本地单机 AI 文字冒险、主要能力及离线模式。
2. 技术架构：FastAPI、SQLite、原生 HTML/CSS/JS、DeepSeek SSE。
3. 核心数据流：作品与角色设定进入会话，AI 输出经解析后更新消息、状态、记忆和存档。
4. 关键文件：启动入口、后端入口、路由、服务、数据库、前端主文件和测试。
5. 常用命令：安装依赖、启动服务、运行后端与前端测试。
6. 当前事实来源：代码、Schema 和测试优先于已过时的说明文档。
7. 协作规范：保护工作树、密钥、数据库和第三方资源，并要求按改动范围验证。

## 强制协作规范

- 开始和结束工作时检查 `git status --short`，不得覆盖、还原或顺带整理已有改动。
- `config.json` 是已跟踪的本地配置文件；不得读取、输出、提交或复制其中的明文 API Key。优先使用 `DEEPSEEK_API_KEY`。
- 不直接修改或提交 `data/app.db`；测试应使用测试夹具或临时数据库。
- 不随意修改 `frontend/vendor/` 的 Live2D 第三方资源；确需修改时同步核对来源和许可证。
- 项目按单进程运行，同一会话的生成锁位于进程内；不得改为多 worker 启动。
- 修改后至少运行相关模块测试；跨前后端改动运行完整的 Python 与 Node 测试套件。
- 保持 UTF-8、现有中文界面、统一 API 错误结构和 SSE 事件约定。
- 优先做范围内的最小改动，不重构无关模块，不自动提交或推送用户未授权的内容。

## 不包含内容

- 不复制完整 API 契约或数据库 Schema。
- 不记录会快速过时的逐项功能清单和具体未提交 diff。
- 不写入任何真实 API Key、用户数据或数据库内容。

## 验收标准

- `AGENTS.md` 位于项目根目录，独立阅读即可开始工作。
- 命令、路径、架构描述与当前代码一致。
- 明确说明工作树保护、密钥保护、单进程限制和测试要求。
- 没有占位符、歧义、秘密或与现有项目约定冲突的指令。
