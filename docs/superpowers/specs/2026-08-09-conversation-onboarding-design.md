# 剧本会话开局引导设计

## 目标

让每个剧本作者定义自己的首次会话引导。玩家打开剧本后可以继续已有对话，或创建新对话；新对话必须先完成该剧本要求的引导字段，随后才进入冒险。填写结果属于该会话，不会修改剧本、角色卡或世界书。

## 范围

- 剧本维护一份可选的开局引导配置。
- 每个剧本详情页展示该剧本的对话列表，并提供继续、新建和删除操作。
- 新建会话先展示动态引导表单；提交成功后写入会话状态和会话元数据。
- AI 上下文包含本次会话的引导回答，使剧情从正确的身份、时间、地点或目标开始。
- 已完成引导的会话直接进入冒险；存档和读档保持现有行为。

不在本次范围内：跨剧本复用引导模板、复杂字段联动、多人协作、修改既有角色卡结构。

## 数据模型与接口

在作品数据中新增 `onboarding`：

```json
{
  "enabled": true,
  "intro": "请补全本次开局设定。",
  "fields": [
    {
      "key": "player_role",
      "label": "你扮演谁？",
      "type": "text",
      "required": true,
      "placeholder": "例如：哲，Random Play 店主",
      "default": ""
    },
    {
      "key": "start_location",
      "label": "开局地点",
      "type": "select",
      "required": true,
      "options": ["Random Play 录像店", "六分街街口"],
      "default": "Random Play 录像店"
    }
  ],
  "allow_freeform": true
}
```

字段类型限定为 `text`、`textarea` 和 `select`。`key` 在同一剧本中唯一，并只允许字母、数字和下划线。后端在创建会话时保存初始引导配置快照，避免剧本后来编辑后改变已有对话的填写语义。

会话新增 `onboarding_status`（`pending` 或 `completed`）、`onboarding_answers`（键值对象）和 `onboarding_config`（创建时的配置快照）。增加一个“完成会话引导”接口：校验必填字段、持久化回答、把回答合并为状态的 `attributes` 或 `flags` 中的可见摘要，并返回更新后的会话。自由补充保存为 `freeform`。

`build_system_prompt` 读取已完成会话的引导回答，并在固定人设和当前状态后附加“本次开局设定”。未完成引导的会话不允许发送聊天请求，返回明确的校验错误。

## 前端交互

剧本详情页将“开始冒险”替换为“对话”区域：

1. 显示该剧本已有会话的标题、最后活动时间和继续按钮；允许删除会话。
2. 点击“新建对话”创建 `pending` 会话，随后导航到引导页。
3. 引导页按剧本配置渲染字段，显示进度与简短说明；无配置时直接完成并进入开场。
4. 提交前在浏览器端检查必填项；服务端成功后进入冒险页。
5. 冒险页只对 `completed` 会话可访问；继续已有会话不显示引导。

创作台在“作品设定”区新增开局引导编辑器：开关、说明、字段列表、字段新增/删除、字段类型、必填、默认值、占位提示和单选项。保存时做键名唯一性与选项完整性校验。

## 错误处理

- 不存在的剧本或会话沿用 404 响应。
- 无效字段配置在保存剧本时返回 422，并指出字段位置。
- 引导提交缺少必填值时返回 422，并列出缺失字段键名。
- 前端提交失败保留用户已填写内容并提示错误，不创建重复会话。
- 打开 `pending` 会话时返回引导页；尝试直接聊天则提示先完成开局设定。

## 测试与验收

- 后端测试：配置校验、创建会话时配置快照、必填校验、回答持久化、上下文注入、未完成引导禁止聊天。
- 前端测试/烟雾验证：剧本详情能列出会话；新建会话进入对应动态表单；填写后可进入并继续对话；已有会话不重复引导；删除与存档功能仍可用。
- 回归运行既有 `backend/smoke_test.py` 和会话并发测试。

## 完成标准

作者能为任意剧本配置专属字段。玩家每次创建新对话只需完成一次该剧本的引导，结果在后续聊天和存档恢复时稳定保留，并被 AI 用作该会话的剧情上下文。
