# 冒险初始属性白名单与 AI 状态更新约束设计

## 目标

限制冒险中的玩家属性和剧情角色属性，使它们只能修改本局开局时已经存在的数字属性，不允许 AI 因剧情自行新增属性或角色。同时把本局可更新的属性明确注入 AI 提示词，让 AI 根据剧情选择正确的已有属性。

## 范围

本次只调整数值属性的状态更新规则，覆盖：

- 左侧状态栏中的玩家属性，例如“学业”“心情”。
- 状态栏中剧情角色的属性，例如角色“心情”“好感度”。
- AI 结构化 `<state_delta>`、可见状态变化兜底解析和模型遗漏状态块时的默认变化。
- 初始属性白名单在新会话、分支会话、旧会话中的保存与读取。

本次不改变金钱、物品、任务、关系、标记和日志的现有合并规则，也不新增前端编辑器字段。

## 数据模型与生命周期

在 `conversations` 表新增 JSON 字段 `attribute_schema`，默认值为 `{}`。它保存会话创建时的不可变属性白名单和初始值，结构如下：

```json
{
  "attributes": {
    "学业": 60,
    "心情": 70
  },
  "characters": {
    "温挽": {
      "心情": 50,
      "好感度": 0
    }
  }
}
```

创建新会话时：

1. 从剧本的 `player_attributes` 生成玩家初始属性。
2. 从会话冻结的角色卡生成剧情角色初始状态，包括现有的 `character_attributes` 和当前初始化逻辑产生的默认属性。
3. 在同一事务中把这些初始属性写入 `attribute_schema`、实时状态和角色卡快照。

会话开始后，剧本或角色卡的后续修改不影响该白名单。创建分支时复制来源会话的 `attribute_schema`，读档时也不重建或覆盖它。

数据库初始化为旧数据库增加该字段。旧会话的空白名单采用兼容回填：优先使用会话已经保存的实时状态和冻结角色卡快照生成一次白名单，并保存回会话；不存在快照时沿用现有作品/角色卡回退逻辑。回填是幂等的，不覆盖已经存在的非空白名单。

## 状态更新流程

所有属性变化都通过统一的后端过滤器后才进入状态合并：

1. 读取会话的 `attribute_schema` 和当前实时状态。
2. 玩家属性只允许匹配 `attribute_schema.attributes` 中的键。
3. 剧情角色只允许匹配白名单中的角色名和该角色的属性键；未知角色不会被创建。
4. 只有初始值和当前值均为数字的属性才可更新；文本属性跳过。
5. 接受已有属性的正负数字变化，例如 `+5`、`-2`；不允许用状态变化创建新键。
6. 过滤后的 delta 才用于持久化、状态事件、消息元数据和玩家可见的“状态变化”提示。

不合法的属性变化被静默丢弃，不影响同一个 delta 中合法的金钱、物品、任务、关系或标记变化。若过滤后没有任何实际变化，状态和日志不新增记录。

`merge_state` 保持可独立测试，并支持传入白名单；`apply_state_delta` 和普通状态更新入口负责取得当前会话白名单并调用过滤逻辑。角色合并不再对未知角色使用 `setdefault`，避免 AI 通过 delta 创建新的剧情角色。

## 默认变化与可见兜底

当模型没有输出 `<state_delta>` 时，默认变化逻辑只从当前已有且为数字的白名单属性中选择目标：

- 优先选择与当前互动相关的已有剧情角色属性。
- 其次选择已有玩家属性。
- 没有任何合适的数字属性时返回空，不创建“心情”等默认字段。

可见的“【状态变化】”兜底解析仍可识别数字行，但解析结果必须经过同一白名单过滤器。过滤失败的属性不会重复显示给玩家。

## AI 提示词

`build_system_prompt` 在当前状态之外，增加本局实际可更新属性的白名单，并明确说明：

- 玩家属性只能写入 `attributes`，且只能使用列出的属性名。
- 剧情角色属性只能写入对应角色的 `characters[name].attributes`。
- 只能修改开局已有的数字属性，使用正负数字变化。
- 必须根据本回合剧情选择真正相关的已有属性，不为了凑状态变化而修改无关属性。
- 禁止新增属性、改名、添加角色或把角色属性写到玩家属性中。
- 没有合适的已有属性时不输出属性变化。

提示词不再用“默认修改心情”这类可能诱导新增字段的泛化表达，而是引用当前会话白名单。后端过滤仍是最终约束，不能依赖模型完全遵守提示词。

## 错误处理与兼容性

- 无效属性名、未知角色和非数字属性不抛出请求错误，直接忽略，以免一条 AI 回复因局部违规而丢失其他合法状态变化。
- 现有状态接口、流式 SSE、存档、读档和前端状态栏继续使用原有结构。
- `attribute_schema` 是会话内部配置，不要求前端编辑或展示。
- 没有属性的剧本仍然可以正常开始冒险；它不会因为兜底逻辑而获得新的属性。
- 现有旧会话可以继续对话；首次读取时的兼容白名单回填不会改变当前实时数值。

## 测试计划

### 后端

- 新会话保存玩家和所有剧情角色的初始白名单及初始值。
- 分支会话复制白名单，且后续属性变化互不影响。
- 合法玩家属性增量只修改已有属性。
- 新玩家属性被忽略。
- 合法剧情角色属性增量只修改对应角色。
- 未知角色和未知角色属性被忽略，不创建新角色。
- 文本属性、空属性状态不会被数字更新或自动创建。
- 混合 delta 仍保留合法的金钱/物品等变化。
- 提示词包含当前实际白名单和禁止新增属性的规则。
- 流式回复的状态元数据和可见提示只包含过滤后的变化。
- 旧会话白名单回填可重复执行且不覆盖已有白名单。

### 前端与回归

- 运行现有状态栏、状态变化显示和冒险流程测试，确认合法数值变化仍能渲染。
- 运行完整 Python 后端测试和现有 Node 前端测试。

## 验收标准

1. 玩家和剧情角色的左侧属性永远不会因 AI 状态变化新增字段。
2. AI 只能修改本局开局时已存在的数字属性。
3. AI 提示词能看到并遵守本局属性白名单，按剧情选择已有属性。
4. 无效变化不会污染数据库，也不会在聊天中伪装成已发生的变化。
5. 新会话、分支会话、旧会话和读档流程均保持可用。
