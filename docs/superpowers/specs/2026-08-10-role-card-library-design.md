# 角色卡库与剧本引用设计

## 目标

将角色卡从剧本编辑器中的嵌入式表单提升为可复用的独立资源：用户可以在顶部“角色卡”入口中搜索、创建、编辑和删除角色卡；剧本只引用已有角色卡；同一张卡可以被多个剧本复用。编辑被引用的角色卡时，明确提示只影响之后新开的会话，已经开始的旧会话保持原样。

本次不新增“初始数值关系”编辑区。已有 `initial_state.relations` 数据保留并在保存角色卡时原样保留，避免旧数据被表单覆盖或误删。

## 现状与约束

- 后端使用 FastAPI + SQLite，`cards` 表已经独立存在，`works.card_id` 已经是外键引用。
- 当前前端只有作品库、创作台和设置导航；角色卡字段与作品字段共用创作台表单。
- 当前创建作品时会同时创建一张新角色卡；当前编辑作品时会原地更新其角色卡。
- 当前会话仅保存 `card_id`，AI 每次组装上下文时读取最新角色卡，因此编辑角色卡会影响旧会话；本次必须修正这一点。
- `cards` 和 `works` 外键均使用 `ON DELETE SET NULL`，删除保护必须在业务层显式执行。
- 应同时支持后端模式、Mock 模式和无后端离线演示模式。
- 根目录不是 Git 仓库，设计文档和代码可以保存，但不能提交 Git commit。

## 方案概览

采用“独立角色卡资源 + 剧本引用”的方案，不引入每个剧本一份副本，也不保留角色卡表单与剧本表单的长期耦合。

数据关系如下：

```text
角色卡 1 ──────< 剧本 N ──────< 会话 N
                         │
                         └── 会话创建时保存角色卡快照
```

角色卡编辑只更新角色卡资源；剧本只更新 `card_id` 引用。新会话读取角色卡当前版本并保存快照，旧会话从自身快照读取。

## 数据与后端设计

### 角色卡 API

保留现有角色卡 CRUD API：

- `GET /api/cards?q=&page=&page_size=`：角色卡库列表与搜索。
- `POST /api/cards`：创建角色卡。
- `GET /api/cards/{card_id}`：读取角色卡详情。
- `PUT /api/cards/{card_id}`：更新角色卡。
- `DELETE /api/cards/{card_id}`：删除角色卡。

角色卡的可编辑字段保持现有模型：`name`、`persona`、`personality`、`speaking_style`、`relationships`、`directives`、`initial_state`、`character_attributes`、`source`。前端不再暴露 `initial_state.relations` 编辑控件，但编辑保存时保留已有值。

删除角色卡时，仓储层按 `works.card_id` 查询引用剧本；若存在引用，路由返回 `409 conflict`，错误信息包含“角色卡正在被剧本引用”以及可用于展示的剧本标识。数据库删除操作不会执行。无引用时才执行删除。

引用数量和剧本名称由前端通过作品列表按 `card_id` 聚合，用于列表摘要、编辑提示和删除提示；后端删除前再次查询，防止前端检查与实际删除之间出现竞态。

### 剧本 API

保留现有 `WorkCreate`、`WorkUpdate` 的 `card_id: Optional[int]`：

- 新建或编辑剧本可以选择已有角色卡。
- `card_id = null` 表示剧本不使用角色卡。
- 保存剧本不再隐式创建或更新角色卡。
- 后端继续校验非空 `card_id` 必须指向存在的角色卡。

### 旧会话隔离

在 `conversations` 表增加 `card_snapshot` JSON 文本列，默认空对象，并在数据库初始化时执行无损迁移：

1. 为已有且仍能找到角色卡的会话复制当前角色卡完整对象。
2. 新建会话时，在同一个创建流程中复制剧本当前引用的角色卡。
3. `row_to_conversation` 将快照解析为对象。
4. AI 引擎组装提示词时，优先使用会话快照；只有历史异常数据没有快照时，才回退读取当前角色卡。
5. 开局确认文本和冒险页角色卡展示也优先使用快照，避免只隔离 AI 而界面仍显示新版本。

角色卡更新不修改任何会话的 `card_snapshot`、状态、消息或存档。新开的会话使用更新后的角色卡；已经开始的旧会话继续使用创建时的角色卡内容。

## 前端页面与交互

### 导航与路由

顶部导航新增“角色卡”入口，指向角色卡库。增加以下页面状态：

- `#/cards`：角色卡库。
- `#/card/new`：创建角色卡。
- `#/card/{id}`：编辑角色卡。
- `#/creator`：创建剧本，只包含剧本、角色卡引用、世界书和开场配置。
- `#/creator/{workId}`：编辑剧本，只更新剧本及其引用关系，不直接编辑角色卡内容。

### 角色卡库

角色卡库提供：

- 名称、人设和性格搜索。
- 角色名、性格摘要、来源、引用剧本数量。
- 创建、编辑、删除操作。
- 删除时优先展示当前引用剧本；即使前端未及时刷新，后端 `409` 仍阻止删除并显示错误。

### 角色卡编辑器

角色卡编辑器迁移当前创作台中的角色卡字段，保留：

- 角色名、人设、性格、说话方式。
- 固定指令。
- 玩家初始属性。
- 剧情角色属性。
- 文字关系。

不渲染初始数值关系区、不提供其新增或删除按钮。编辑已有卡时，提交的 `initial_state` 以原值为基础仅更新表单仍负责的字段。

当角色卡被剧本引用时，编辑页显示固定提示：

> 此角色卡已被 X 个剧本引用，保存后会影响这些剧本之后新开的会话；已经开始的旧会话不会改变。

保存前再次确认，避免用户误以为修改只作用于当前剧本。没有引用时不显示影响剧本列表。

### 剧本编辑器

作品信息区域增加角色卡下拉框：

- 选项包含“不使用角色卡”和所有可用角色卡。
- 选择后显示角色卡名称/性格摘要，提供跳转到角色卡库的入口。
- 创建剧本时只提交 `card_id`，不创建角色卡。
- 编辑剧本时只更新 `works.card_id`，不更新被引用角色卡的内容。
- 角色卡编辑入口与剧本保存相互独立，避免一次提交同时改动两个资源。

### 离线与 Mock 模式

扩展现有 Mock 数据结构，在本地存储中增加独立 `cards` 数组；首次读取旧格式时从作品中的嵌入卡按 `card_id` 去重生成卡库，并让作品继续通过 `card_id` 查卡。离线模式实现与后端模式一致的角色卡列表、编辑、引用计数和被引用删除阻止行为。

## 错误处理

- 空角色名继续由现有前后端校验拒绝。
- 非法或不存在的 `card_id` 继续返回校验错误。
- 删除被引用角色卡统一显示“角色卡正在被剧本引用”，并列出剧本名；不依赖 SQLite 的 `SET NULL` 兜底。
- 角色卡编辑加载失败时保留页面错误状态，不提交半成品数据。
- 保存角色卡或剧本失败时恢复按钮状态并保留当前表单内容。
- 对旧会话快照迁移使用幂等逻辑；重复启动不会覆盖已有快照。

## 测试策略

### 后端

新增或扩展单元测试覆盖：

1. 角色卡被剧本引用时删除抛出/返回冲突。
2. 未被剧本引用的角色卡可以删除。
3. 新建会话保存角色卡快照。
4. 角色卡更新后，旧会话构建的系统提示仍包含旧卡内容。
5. 角色卡更新后，新会话构建的系统提示使用新卡内容。
6. 角色卡快照迁移只填充空快照，不覆盖已有快照。

### 前端

新增源级回归测试覆盖：

1. 顶部角色卡导航和 `cards/card` 路由存在。
2. 角色卡库包含搜索、创建、编辑、删除入口。
3. 剧本表单包含角色卡选择器，并以 `card_id` 保存。
4. 剧本提交路径不再调用 `POST /api/cards`。
5. 角色卡编辑器保留角色属性、文字关系字段。
6. 不再渲染初始数值关系编辑区。
7. 被引用删除和编辑影响提示存在。

实现后运行现有 Python 后端测试、现有 Node 前端测试、相关新增测试以及 `node --check frontend/js/main.js`。

## 成功标准

- 用户能从顶部角色卡入口完成角色卡搜索、创建、编辑和删除。
- 一个角色卡能被多个剧本引用，创建/编辑剧本不会自动复制或创建角色卡。
- 被剧本引用的角色卡不能删除。
- 编辑被引用角色卡时界面明确提示影响范围和新旧会话边界。
- 已开始会话的 AI 上下文和界面角色卡内容不因后续卡片编辑改变。
- 现有作品、角色卡、世界书、会话和离线演示数据不丢失。
