# 聊天窗口与字体放大设计

## 背景

冒险聊天页当前的消息区域在桌面端横向空间偏紧，消息文本和输入框文字的阅读尺寸也偏小。用户希望聊天窗口横向、纵向都略微增大，并同步放大聊天相关字体。

## 目标

- 只调整冒险聊天页，不改变作品库、创作台、设置等其他页面的布局比例。
- 桌面端聊天面板横向增加可用空间，纵向略微增加高度。
- 放大消息正文和输入框字体，提升连续阅读与输入体验。
- 保持状态侧栏、快捷指令、消息发送逻辑和响应式行为不变。

## 方案

在现有 `frontend/css/style.css` 的最终视觉覆盖区增加聊天页专用样式：

- 使用聊天页结构选择器，将更宽的应用容器规则限定在包含 `.adventure-shell` 的页面。
- 桌面端将聊天页应用容器最大宽度从当前约 1240px 提高到约 1400px，让聊天主面板获得更多空间；聊天页高度增加约 16px。
- 消息正文使用约 17px 字体和更舒适的行高；系统提示、消息标签、会话标题和输入框同步做小幅放大，保持层级关系。
- 在窄屏下继续使用单列布局，并将消息正文控制在约 16px，避免移动端横向溢出。
- 不增加新的运行时状态，不改变 HTML 结构和 JavaScript 交互逻辑。

## 影响范围

### 修改文件

- `frontend/css/style.css`

### 不修改内容

- 消息加载、发送、流式响应和快捷指令逻辑。
- 状态侧栏的显示、折叠和移动端浮层行为。
- 后端 API、数据结构和本地 Mock 数据。
- 非聊天页面的尺寸与排版。

## 验证

1. 使用现有前端测试或启动方式打开冒险聊天页。
2. 在桌面视口确认聊天面板横向、纵向均比当前更大，且状态侧栏仍完整可见。
3. 确认 AI 消息、用户消息、系统提示和输入框文字均清晰放大。
4. 在窄屏视口确认聊天页仍为单列，输入区不横向溢出。
5. 检查 `frontend` 目录下的现有测试，确保本次 CSS 调整没有引入脚本错误。
