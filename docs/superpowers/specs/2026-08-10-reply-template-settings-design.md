# 作品回复模板设置设计

## 目标

在作品编辑页增加多套 AI 回复模板。用户可以为同一个作品保存多个模板，并在作品设置页选择一个当前模板。聊天页不提供模板切换控件；当前模板会在后续 AI 回复中作为输出格式与写法约束使用。

模板不是固定的机器人回复，而是给模型的可编辑指令，例如要求回复包含正文、状态栏或剧情选项。没有当前模板时，保持现有回复行为。

## 现状与约束

- 后端使用 FastAPI + SQLite，作品字段由 `works` 表和 `WorkCreate` / `WorkUpdate` 管理。
- 作品编辑页由 `frontend/js/main.js` 的 `renderCreator`、`fillCreatorForm` 和 `submitCreatorForm` 负责。
- AI 上下文由 `backend/services/adventure_engine.py` 的 `build_system_prompt` 组装。
- 作品数据已有 JSON 字段（标签、开场引导等），可用一个 JSON 列保存模板数组，避免新增资源 CRUD 和额外页面。
- 需要保留在线 API、Mock/offline 模式与现有旧作品数据。
- 当前工作区不是 Git 仓库，因此设计文档无法提交 commit。

## 方案

在 `works` 表增加两个字段：

- `reply_templates TEXT NOT NULL DEFAULT '[]'`：模板数组，每项包含稳定的字符串 `id`、`name`、`content`。
- `active_reply_template_id TEXT NOT NULL DEFAULT ''`：当前模板 ID；空字符串表示不启用模板。

`row_to_work` 将 `reply_templates` 解析为列表，返回作品详情和列表接口。创建、更新接口接收并保存这两个字段。更新时校验模板结构：模板必须是对象列表，名称和内容转为字符串，空模板项被忽略；当前 ID 不存在时自动清空，避免引用失效模板。

## 前端交互

作品设置页在“开场剧情”之后增加“回复模板”区：

- 每个模板显示名称输入框、内容文本框、当前模板单选按钮和删除按钮。
- 提供“添加模板”按钮。
- 作品保存时一次性提交模板列表和当前模板 ID。
- 编辑作品时加载并恢复模板列表及当前选择。
- 新建作品可以先不添加模板。
- 不在聊天页展示模板选择器，避免改变既定交互范围。

离线模式使用同一字段形状保存到现有 Mock 数据，不引入第二套格式。

## AI 上下文

`build_system_prompt` 读取作品的模板数组和当前 ID，只将匹配的模板追加到系统提示中。模板内容放在输出规则附近，明确它是“回复格式指令”，但仍需遵守角色卡、世界书、状态块和选项块规则。模板为空或当前 ID无效时不追加任何内容。

切换模板后，后续请求读取最新作品设置；历史消息不被修改。

## 测试策略

后端测试覆盖：

1. 旧数据库自动迁移后，作品模板字段默认为空。
2. 创建和更新作品可以保存、读取多个模板及当前 ID。
3. 无效当前 ID 会被清空，空模板项不会进入持久化结果。
4. 系统提示只包含当前模板，不包含未选模板。
5. 无模板时系统提示与现有行为一致。

前端测试覆盖：

1. 作品编辑器包含多模板编辑区、添加、删除和当前模板选择控件。
2. 编辑加载时恢复模板内容和当前选择。
3. 创建和更新请求提交 `reply_templates` 与 `active_reply_template_id`。
4. 聊天页没有模板切换控件。

## 成功标准

- 用户能在作品编辑页保存多套模板。
- 用户能在同一页选择当前模板并再次打开后保持选择。
- 后续 AI 回复使用当前模板，未选模板时不改变原有行为。
- 现有作品、会话、世界书、Mock 数据和测试不回归。
