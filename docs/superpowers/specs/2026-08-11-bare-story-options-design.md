# 无标题剧情选项解析修复设计

## 目标

当模型没有输出 `选项：` 标题或 `<options>` 结构化块，而是直接连续输出两到四行项目符号/编号选项时，系统仍能识别模型原本给出的行动，不再替换成通用兜底选项。

## 现状与根因

- `backend/services/adventure_engine.py` 的 `parse_visible_options` 只有在识别到 `选项`、`可选行动` 或 `行动` 标题后才开始收集项目符号。
- 本次回复直接输出四行 `- ...`，随后输出可见的 `【状态变化】`，因此该函数返回空结果。
- `backend/routers/chat_routes.py` 随后调用 `default_turn_options`，生成“观察周围”等通用选项并通过 SSE 发送给前端。
- 前端优先使用 SSE 中的显式选项，所以不会再使用自身的隐式项目符号提取逻辑。

## 设计

扩展后端可见选项解析器：

1. 保留现有的标题列表和 `<options>` 结构化解析路径。
2. 当尚未进入标题列表时，识别连续的项目符号或编号行作为候选列表。
3. 只有候选列表至少包含两项时才返回，避免单行叙事列表被误判为按钮。
4. 遇到普通正文、`【状态变化】` 或其他非选项行时结束候选列表；最多返回四项。
5. 复用现有清理逻辑，去除项目符号、编号和首尾引号。

不修改前端显式选项优先级，也不依赖模型提示词必须遵守格式；结构化选项仍然是优先路径。

## 测试与验收

- 在 `backend/test_options_output.py` 增加无标题连续项目符号列表的回归测试，覆盖本次塞西莉亚回复的四个选项并确认状态块不会被收进选项。
- 先运行该测试确认当前实现失败，再实现解析器并确认测试通过。
- 运行完整后端测试以及现有前端 Node 测试。

验收结果：该回复应产生四个原始行动选项，而不是“观察周围、尝试接近、寻找其他入口”等兜底选项；结构化选项和带标题列表的既有行为保持不变。
